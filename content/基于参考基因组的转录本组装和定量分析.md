## 从read重构isoform

测序仪输出的是短片段（Reads），而生物学研究对象是全长的转录本（Transcripts）。

这构成了所谓的“逆问题”（Inverse Problem）。我们需要从大量的、破碎的观测数据中，反推回原始的序列结构及其相对丰度。

### 参考基因组引导 vs. 从头组装

主要有两种策略：基于参考基因组的组装（Reference-based）与从头组装（De novo）。

- 从头组装（De novo）：
    
    类似于在没有原图的情况下拼拼图。它完全依赖 Reads 之间的重叠关系（Overlap）来构建序列。
    
    - 适用场景： 无参考基因组物种。
        
    - 局限性： 对计算资源要求极高；极易受测序错误和高丰度转录本的干扰，难以准确重构低丰度转录本。
        
- 基于参考基因组（Reference-based）：
    
    类似于在已有的线稿上进行填色和细节修补。首先将 Reads 比对（Map）到基因组上，形成簇（Clusters），再在簇内进行组装。
    
    - 为什么在有参考基因组时更优： 参考基因组提供了准确的“坐标系”和“内含子-外显子边界”先验信息。这极大降低了搜索空间，使得算法能够更敏感地捕捉低丰度转录本，并准确区分旁系同源基因（Paralogs）。
        

本文将以 StringTie 为例，探讨如何在已知参考基因组骨架的引导下，利用流网络算法解决这一问题。

## StringTie 实例：非 -e 模式下的发现与定量

默认运行模式（即不加 `-e` 参数）

```Bash
# 第一步：将 Reads 比对到基因组（生成 BAM 文件）
hisat2 -p 8 -x hg38_index -1 sample_1.fq.gz -2 sample_2.fq.gz | \
samtools sort > sample.sorted.bam

# 第二步：StringTie 组装与定量（核心步骤）
stringtie sample.sorted.bam \
    -G hg38_annotation.gtf \
    -o sample.gtf \
    -p 8 \
    -A gene_abundances.tab \
    -B
```

### 输入

1. SAM/BAM Mapping 结果：
    这是真实的观测数据。StringTie 依赖比对位置形成的“覆盖度岛屿”来确定转录本可能存在的区域。
2. 参考注释 GTF (-G)：
    在非 -e 模式下，这个文件仅作为“启发式引导”。
    - 算法会利用 GTF 中的外显子坐标构建初始的剪接图节点。
    - 关键点： 算法不受限于 GTF。如果测序数据中有强有力的证据（如大量的 Junction Reads）支持一个新的剪接位点或外显子，StringTie 会在输出中构建新的结构。此时，参考 GTF 只是一个起点，而非终点。
        

### 输出

输出文件 `sample.gtf` 包含了重构后的所有转录本结构。
- 结构发现： 输出中不仅包含已知的转录本，还可能包含新的 Isoform（同源异构体）。
- 定量结果： 包含 FPKM/TPM 值。
- Ballgown 目录 (`-B`)： 输出专门用于后续差异表达分析的结构化文件。

> [!TIP] 版本号的含义
> 
> 在 StringTie 的输出中，你经常会看到如 STRG.1.1 或 STRG.1.2 的 ID。
> 
> - 这代表了算法内部的迭代优化过程。
>     
> - 后缀的递增（.1, .2）并不意味着生物学上的“版本”，而是同一基因座（Locus）下不同转录本的标识。这有助于追踪转录本在多次组装迭代中的变化。
>

## 算法核心：流网络与贪婪优化

StringTie 的核心是将转录本重构问题转化为流网络（Flow Network）中的最大流问题。

### 剪接图（Splice Graph）

算法首先根据 Reads 的比对情况构建剪接图：
- 节点（Nodes）： 代表外显子（Exons）。
- 边（Edges）： 代表连接外显子的 Reads（Junction Reads）。
- 流量（Flow/Capacity）： 节点的流量由覆盖该外显子的 Reads 总数决定。
    

### 流入与流出（Inflow & Outflow）

为了应用网络流理论，我们必须定义流动的方向。假设转录方向是从 5' 到 3'：
- 流入（Inflow）： 进入一个节点的流量。来源包括转录起始点（TSS）或上游外显子的连接边。
- 流出（Outflow）： 离开一个节点的流量。去向包括转录终止点（TES）或连接到下游外显子的边。
    

流守恒定律（Conservation of Flow）：
在理想的无噪声状态下，对于一个完整的转录本，中间任意一个外显子节点的流入量应等于流出量。

$$Inflow(v) = Outflow(v)$$

如果观测数据违反了这一守恒（例如流入远大于流出），通常暗示这里存在转录本的起始、终止，或者存在未被识别的 Alternative Splicing（可变剪接）。

### Super-reads：降噪的关键

这是 StringTie 区别于早期工具（如 Cufflinks）的关键创新。

- 如果不使用 Super-reads：
    原始的剪接图由每一个单独的 Read 构成。由于短读长的模糊性，图中会包含大量冗余的节点和边，形成一个复杂的“毛线团”（Hairball）。这会导致计算量爆炸，且容易产生虚假的转录本路径。
    
- StringTie 的策略：
    算法首先利用双端测序（Paired-end）信息，将相互兼容的 Reads 预组装成 Super-reads。
    Super-reads 本质上是更长的、高置信度的片段。利用 Super-reads 构建剪接图，极大地稀疏化了网络，保留了真实的结构信号，剔除了随机测序噪声。

## 优化求解：重构与定量的迭代

构建好流网络后，问题转化为：如何找到一组路径（转录本），使得它们能最大程度地解释图中的总流量。

这是一个贪婪的迭代过程：

1. 寻找最重路径：
    在剪接图中寻找一条连通的路径，该路径上的平均覆盖度（流量）最高。算法假设覆盖度最高的路径代表主要转录本（Major Isoform）。
2. 估算丰度：
    根据路径上的流量估算该转录本的丰度。
3. 流量减除（Flow Subtraction）：
    这是最关键的一步。算法根据估算的丰度，从图中减去该路径所对应的流量。
    - 如果一个外显子被该路径完全解释，其剩余流量归零。
    - 如果一个外显子同时属于其他低丰度转录本，减去后会保留剩余流量。
4. 迭代：
    在剩余的“残差图”中重复上述步骤，直到剩余的流量低于背景噪声阈值。
    

### 边界情况处理

- 单外显子 Read： 如果 Reads 完全落在一个外显子内，不跨越边界，它们主要贡献节点的权重（覆盖度），但不提供连接信息。
- Intron Retention（内含子保留）： 如果连续的 Reads 覆盖了本应是内含子的区域，StringTie 会判断其覆盖度。若高于噪声阈值，则可能将其识别为 Retained Intron 或新的 Exon；若过低，则视为未成熟的 pre-mRNA 噪声被丢弃。

## 对比视角：转录本组装 vs. 基因组组装

虽然两者都涉及“组装”，但本质截然不同。

|特征|基因组组装 (Genome Assembly)|转录本组装 (Transcript Assembly)|
|---|---|---|
|基本单元|DNA 片段|RNA 片段（cDNA）|
|图模型|De Bruijn Graph (基于 K-mer)|Splice Graph (基于 Exon/Intron)|
|数学目标|还原拼图 (Puzzle Solving)|混合物解卷积 (Mixture Deconvolution)|
|核心挑战|寻找单一的欧拉路径或哈密顿路径。目标是重建唯一的、原本存在的基因组序列。|寻找多条路径的线性组合。同一个基因座会产生多个 Isoform，且它们的丰度跨越数个数量级。|
|边的权重|权重通常只用于排除错误，不代表生物学意义（因基因组拷贝数通常固定）。|权重（流量）是核心信息，代表了转录本的表达量。|

## 总结

StringTie 通过引入 Super-reads 简化了剪接图的复杂性，并利用流网络算法，将生物学上的“异构体共存”问题转化为数学上的“多路径流量分配”问题。它不仅利用参考基因组作为骨架，更保留了数据驱动的灵活性，从而实现了对转录本结构和丰度的还原。
