## 动机

在进行科学计算、图形渲染或深度学习模型推理时，我们经常需要处理一连串的矩阵乘法，例如 $A_1 A_2 A_3 A_4$。

矩阵乘法满足结合律， $(A_1 A_2) A_3$ 和 $A_1 (A_2 A_3)$ 的最终结果是相同的。这是否意味着计算顺序无关紧要？

让我们看一个实例。假设有四个矩阵，维度如下：
* $A_1$: $1000 \times 5$
* $A_2$: $5 \times 500$
* $A_3$: $500 \times 10$
* $A_4$: $10 \times 100$

**方案一：最“直观”的顺序，从左到右 $((A_1 A_2) A_3) A_4$**
1.  $D_1 = (A_1 A_2)$：代价 $1000 \times 5 \times 500 = 2,500,000$ ( $D_1$ 维度 $1000 \times 500$ )
2.  $D_2 = (D_1 A_3)$：代价 $1000 \times 500 \times 10 = 5,000,000$ ( $D_2$ 维度 $1000 \times 10$ )
3.  $D_3 = (D_2 A_4)$：代价 $1000 \times 10 \times 100 = 1,000,000$
4.  **总代价 (乘法次数)：$2.5M + 5M + 1M = 8,500,000$**

**方案二：一种“最优”的顺序 $A_1 ((A_2 A_3) A_4)$**
1.  $E_1 = (A_2 A_3)$：代价 $5 \times 500 \times 10 = 25,000$ ( $E_1$ 维度 $5 \times 10$ )
2.  $E_2 = (E_1 A_4)$：代价 $5 \times 10 \times 100 = 5,000$ ( $E_2$ 维度 $5 \times 100$ )
3.  $E_3 = (A_1 E_2)$：代价 $1000 \times 5 \times 100 = 500,000$
4.  **总代价 (乘法次数)：$25k + 5k + 500k = 530,000$**

> [!WARNING] 性能差异
> 8,500,000 次乘法 vs 530,000 次乘法。
>
> 仅仅是改变了计算顺序，我们获得了超过 **16 倍** 的性能提升。这种优化是纯粹的算法策略优化，不损失任何精度。相比之下，我们费力地去做 SIMD 指令集优化或多线程并行，可能带来几倍的性能提升；而一个不恰当的结合顺序，就可能让这些底层优化全部白做。
>
> 我们的目标就是：找到这个“最优结合顺序”。

## 问题的形式化定义

首先，我们明确单个矩阵乘法的代价。计算一个 $A_{p \times q}$ 矩阵和一个 $B_{q \times r}$ 矩阵的乘积 $C_{p \times r}$，需要进行的标量乘法次数为 $p \times q \times r$。

对于一个矩阵链 $A_1 A_2 \dots A_n$，假设 $A_i$ 的维度是 $p_{i-1} \times p_i$。那么这一系列矩阵的维度可以用一个形状列表（shape list）来表示：
$$
P = (p_0, p_1, p_2, \dots, p_n)
$$
例如，引子中的例子，其 `shape_list` 就是 `[1000, 5, 500, 10, 100]`。

我们的问题是：为 $A_1 \dots A_n$（对应 $P[0 \dots n]$）找到一种加括号的方式，使得总的标量乘法次数最少。


> [!warning] 多少种计算顺序? 
> 对于 $n$ 个矩阵的链，总共有多少种结合方式呢？这并不是 $(n-1)!$ (阶乘) 种，而是由著名的**卡特兰数 (Catalan number)** 决定的，其值为 $C_{n-1} = \frac{1}{n} \binom{2n-2}{n-1}$。

## 拆分子问题与递归解法

这个问题具有**最优子结构**（Optimal Substructure）的特性。
我们要计算 $A_i \dots A_j$ 的最小代价，记为 $m(i, j)$。
那么，无论最优解是什么，它必然是在某个 $k$ 值 ( $i \le k < j$ ) 处进行了最后一次乘法，即：
$$
(A_i \dots A_k) \times (A_{k+1} \dots A_j)
$$
这个 $k$ 将原问题分成了两个子问题： $m(i, k)$ 和 $m(k+1, j)$。
$A_i \dots A_k$ 的结果是一个 $p_{i-1} \times p_k$ 的矩阵。
$A_{k+1} \dots A_j$ 的结果是一个 $p_k \times p_j$ 的矩阵。

合并这两个子问题的代价是 $p_{i-1} \times p_k \times p_j$。
因此，我们可以得到状态转移方程：
$$
m(i, j) = \min_{i \le k < j} \{ m(i, k) + m(k+1, j) + p_{i-1} p_k p_j \}
$$
当 $i=j$ 时， $m(i, i) = 0$ (单个矩阵，不需要计算)。


> [!NOTE] 递归：自顶向下的思考
> 解决这个问题的最自然的方式是递归。我们要计算 $A_i \dots A_j$ 的最小代价，在我们的代码实现中，使用 `shape_list` $P$ 和索引 `[i, j)`（左闭右开区间，对应 $P[i]$ 到 $P[j]$）来定义问题。
>
> `minNumMul(i, j)` 表示计算 $A_i \dots A_{j-1}$ 的最小代价。
>
> 我们的“最后一步”一定是在某个 $k$ 处 ( $i < k < j$ )，将链条分为 $(A_i \dots A_{k-1})$ 和 $(A_k \dots A_{j-1})$ 两部分。
>
> * 左半部分 `minNumMul(i, k)`，结果维度 $P[i] \times P[k]$
> * 右半部分 `minNumMul(k, j)`，结果维度 $P[k] \times P[j]$
> * 合并代价：$P[i] \times P[k] \times P[j]$

```python
shape_list = [10, 20, 30, 10]  # 3个矩阵：A(10×20), B(20×30), C(30×10)

def minNumMul(i, j):
    # [i, j) 左闭右开区间
    num_matrices = j - i
    
    # 基础情况1：空区间或单个矩阵，代价为0
    if num_matrices <= 1:
        return 0
    
    # 基础情况2：两个矩阵，直接计算代价
    if num_matrices == 2:
        # 区间 [i, i+2) 包含矩阵 i 和 i+1
        # 矩阵i的维度是 shape_list[i] × shape_list[i+1]
        # 矩阵i+1的维度是 shape_list[i+1] × shape_list[i+2]
        return shape_list[i] * shape_list[i+1] * shape_list[i+2]
    
    numMul_list = []
    # k 的取值范围：从 i+1 到 j-1
    # 因为切分点k要把 [i, j) 分成 [i, k) 和 [k, j)
    # 两个子区间都不能为空
    for k in range(i + 1, j):
        left_cost = minNumMul(i, k)    # 左子链 [i, k) 的代价
        right_cost = minNumMul(k, j)   # 右子链 [k, j) 的代价
        
        # 合并代价：左结果维度 shape_list[i] × shape_list[k]
        #           右结果维度 shape_list[k] × shape_list[j]
        merge_cost = shape_list[i] * shape_list[k] * shape_list[j]
        
        total_cost = left_cost + right_cost + merge_cost
        numMul_list.append(total_cost)
    
    return min(numMul_list)

# 测试整个矩阵链 [0, 3) (即 A_0, A_1, A_2)
# shape_list 长度为 4 (p0, p1, p2, p3)
result = minNumMul(0, 3) 
print(f"最小乘法次数: {result}")
```

> 这同样是一个指数级增长的数列。上面的递归解法虽然清晰，但它会指数级地重复计算相同的子问题（例如 `minNumMul(2, 4)` 会被 `minNumMul(1, 4)` 和 `minNumMul(2, 5)` 等多次调用）。

## 动态规划

“重叠子问题”也可以自底向上” (Bottom-Up) 地解决问题。


> [!INFO] 动态规划：自底向上的实现
> 我们的策略是“自底向上” (Bottom-Up)：
> 1.  创建一个二维数组 `cost[i][j]`，用于存储计算 `shape_list` 中 `[i, j)` 区间（即 $A_i \dots A_{j-1}$）的最小代价。
> 2.  我们不从最长的链 `cost[0][n]` 开始，而是从最短的链开始。
> 3.  **链长度 $L=1$** (如 $A_1$)：`cost[i][i+1] = 0`。
> 4.  **链长度 $L=2$** (如 $A_1 A_2$)：`cost[i][i+2]` 可以直接算出。
> 5.  **链长度 $L=3$** (如 $A_1 A_2 A_3$)：`cost[i][i+3]` 可以利用 $L=1$ 和 $L=2$ 的结果。
> 6.  ...
> 7.  我们沿着 DP 表的对角线，逐步计算更长的链，直到我们计算出 `cost[0][n]`，即为最终答案。

以下是使用动态规划的实现：

```python
def minNumMul(shape_list):
    # n 是 shape_list 的长度
    n = len(shape_list)
    # cost[a][b] 存储 shape_list[a...b] (即 A_a ... A_b-1) 的最小代价
    cost = [[[] for _ in range(n)] for _ in range(n)]

    # k 代表链的长度 (j-i)
    for k in range(0, n):
        for i in range(0, n-k): # i 是起始点 a
            a,b = i, i+k  # a 是起始点, b 是结束点 (不含)
            
            # 长度为 0 或 1 (k=0 或 k=1)
            if k<=1:
                cost[a][b] = 0
            
            # 长度为 2 (k=2) (例如 A_a, A_a+1)
            elif k==2:
                cost[a][b] = shape_list[a] * shape_list[a+1] * shape_list[a+2]
            
            # 长度大于 2
            else:
                min_cost = float('inf')
                # w 是切分点，遍历所有可能的切分
                for w in range(a+1,b): # 切分 (a, w) 和 (w, b)
                    # 合并 (a...w) 和 (w...b) 的代价
                    merge_cost = shape_list[a] * shape_list[w] * shape_list[b]
                    sub_cost = cost[a][w] + cost[w][b]
                    _cost = merge_cost + sub_cost
                    if _cost < min_cost:
                        min_cost = _cost

                cost[a][b] = min_cost
    
    # 最终答案存储在 cost[0][n-1] 中
    # (对应 shape_list[0...n-1] 的完整链)
    return cost[0][n-1]

# shape_list = [10, 20, 30, 10]
result_dp = minNumMul(shape_list)
print(f"DP 最小乘法次数: {result_dp}")
```

## 算法复杂度最低的就是最快的?

我们通过动态规划，将一个指数级的暴力枚举问题，优化到了 $O(n^3)$ 的时间复杂度（$n$ 是矩阵个数）来找到了乘法次数的最优解。

然而，在高性能计算领域，**乘法次数最少，不一定等于实际运行时间最短。**

我们的 $O(n^3)$ 算法模型有一个隐含的假设：每次乘法代价都是 $O(1)$。但在现代计算机体系结构中，这个假设并不成立。访问内存(RAM)的速度远慢于访问CPU高速缓存(L1/L2/L3 Cache)。

**一个具体的例子：缓存颠簸 (Cache Thrashing)**

假设动态规划告诉我们，对于 $A_1 A_2 A_3 A_4$，理论最优解是 $(A_1 A_2) (A_3 A_4)$。

* $A_1 A_2$ 产生了一个**巨大**的中间矩阵 $D_1$。
* $A_3 A_4$ 产生了一个**巨大**的中间矩阵 $D_2$。

假设 $D_1$ 和 $D_2$ 非常大（例如，都是 $4096 \times 4096$ 的双精度矩阵，各自占用 128MB 内存）。而你的 CPU L3 缓存可能只有 32MB。

当计算 $D_1 \times D_2$ 时，CPU 无法将任何一个矩阵完整读入高速缓存。计算 $D_1$ 的第一行与 $D_2$ 的第一列时，需要从内存中加载 $D_2$ 的整列；计算 $D_1$ 的第一行与 $D_2$ 的第二列时，又可能需要重新从内存加载 $D_2$ 的列（如果缓存已被 $D_1$ 的数据挤出）。

这导致 CPU 在大部分时间里都在“等待内存”，而不是在“计算”。

**对比次优解：**

假设存在一个次优解 $A_1 (A_2 (A_3 A_4))$，它的乘法次数多了 20%。

但是，它的计算过程中产生的中间结果 $E_1 = (A_3 A_4)$ 和 $E_2 = (A_2 E_1)$ 都非常小（例如 $100 \times 100$），可以被完整地装入 L1 缓存。

尽管乘法次数更多，但由于它最大化了**数据局部性 (Data Locality)**，几乎所有计算都在CPU的高速缓存中完成。

**结论：** 这个“次优”解的实际运行时间，可能远远快于那个导致“缓存颠簸”的“理论最优”解。

> [!TIP] 延伸
> 这也解释了为什么高性能计算库 (如 BLAS, cuBLAS, MKL) 内部实现如此复杂。它们不仅考虑了结合顺序，还使用了“分块矩阵乘法”(Tiling / Blocking) 等技术，将大矩阵切分为可以装入缓存的小块进行计算，以确保计算单元始终“有活干”，而不是“等内存”。
